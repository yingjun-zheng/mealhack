# MealHack · 套餐黑客

把麦当劳套餐从"只能凭感觉挑"还原成**可穷举、可核价、可求解**的组合空间。

## 核心原则

**只算，不猜。**

麦当劳套餐的每一项都是可替换的，一个三件套就有 154 种合法组合。这个空间人脑不可能在点餐的 30 秒里穷举完，但机器可以——而且可以用官方 `calculate-price` 逐一核价，不下单、不花钱。

所以本 Skill 永远给"算出来的结论"，绝不给"感觉上不错"的推荐。

## 何时触发

- "这个套餐怎么点最划算"
- "同样的钱怎么换到最多蛋白质"
- "有没有比默认搭配更好的选法"
- "我想减脂 / 增肌，麦当劳怎么吃"
- "套餐里换点什么更值"

## 前置条件

需要环境变量 `MCD_MCP_TOKEN`（申请：https://open.mcd.cn/mcp 手机号登录 → 控制台 → 激活）。

缺失时直接告诉用户去申请，不要尝试用假数据跑。

## 执行流程

所有命令在项目根目录（含 `src/` 的目录）执行。

### 1. 确定门店

问用户城市 + 地标，或让用户直接给 `storeCode`。

```bash
python src/solve.py --list-meals --city 沈阳 --keyword 太原街
```

这会列出该门店所有套餐及其**现价与原价**。原价是单品拆分价之和，所以能直接看出每个套餐的折扣力度（实测同一门店从 1.0x 到 2.34x 不等）。

### 2. 求解

```bash
python src/solve.py --meal <套餐code> --city <城市> --keyword <地标>
```

默认会对 12 个组合抽样调 `calculate-price` 交叉验证；加 `--full-verify` 则全量核价（154 组合约 25 秒）。

### 3. 解读输出（关键）

按这个顺序讲给用户，不要直接把表格甩出去：

1. **先说拐点方案**——这是最该推荐的那一个，因为它是"再加钱就不划算"之前的最后一档。
2. **给出与默认搭配的量化差额**：便宜/贵多少、热量差多少、蛋白质差多少。
3. **解释为什么不再往上加**：引用边际收益表，指出断崖在哪一段（例如"36 元往上，8.5 元只换 2g 蛋白"）。
4. **按用户目标补一条榜**：减脂给低热量榜，增肌给每元蛋白榜，省钱给最便宜榜。
5. **必须说明数据边界**：缺营养数据的菜品已被排除出组合空间，组合数因此少于理论值。

## 输出示例

真实运行结果（麦辣鸡腿汉堡三件套，现价 33.50 元）：

| | 实付 | 热量 | 蛋白质 |
|---|---|---|---|
| 默认（中薯条 + 可乐中杯） | 33.50 | 921 | 28.0 |
| 拐点（大薯条 + 纯牛奶） | 36.00 | 993 | 37.0 |
| 差额 | +2.50 | +72 | +9.0 |

边际收益里，32→33 元这一段每元能换 7g 蛋白，而 36→44.5 元这一段每元只换 0.24g。**断崖就在这里。**

## 禁止事项

- **不许编造营养数据。** 营养表里没有的餐品，直接排除出组合空间，绝不能按 0 计入——那会让它在"低热量榜"上虚假登顶。
- **不许声称"保证最便宜"。** 价格随门店、时段、优惠券变化，结论只对当次核价有效。
- **不许跳过核价直接给结论。** 本地推算必须至少抽样与官方 `calculate-price` 交叉验证。
- **不许把默认搭配当成最优解**，它通常不是。

## 已知限制

- 部分新品（如节令限定）不在营养表里，会被排除，导致组合数少于理论值。
- 套餐的 `supportModify` 特调项（去酱、加菜）目前未纳入枚举——它改变营养但不改变价格，留作后续版本。
- 不调用 `create-order`，本 Skill 不会产生任何真实订单。
